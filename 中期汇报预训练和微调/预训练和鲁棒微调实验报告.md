# 中期汇报：手写数字识别模型的预训练与鲁棒微调

## 1. 实验背景与目标

本项目任务是对 0-9 手写数字图像进行分类识别。基础目标是让模型在标准手写数字数据集上取得较高准确率；进一步目标是增强模型对真实手写场景的适应能力，包括多书写人差异、数字大小变化、位置偏移、轻微旋转、切割不完美、笔画粗细变化、笔画深浅变化、断笔、连笔、墨迹扩散、模糊和噪声等情况。

本阶段采用两步训练策略：

1. **预训练阶段（Clean Expert）**：使用较标准的多源手写数字数据训练基础模型，使其具备较强的标准数字识别能力。
2. **鲁棒微调阶段（Robust Expert）**：从预训练模型出发，引入更强的数据增强和更多真实书写风格数据，使模型对复杂输入更稳健。

预训练过程主要在 `pretraining_notebook.ipynb` 中完成；鲁棒微调、评估和 ensemble 搜索在 `fine-tune_notebook.ipynb` 中完成。

---

## 2. 模型结构

本实验使用 `medium_cnn` 作为主模型。该模型由多层卷积、BatchNorm、ReLU、MaxPool、AdaptiveAvgPool 和 Dropout 分类头组成。

模型规模如下：

| 项目 | 数值 |
|---|---:|
| 模型名称 | medium_cnn |
| 参数量 | 251,562 |
| 可训练参数量 | 251,562 |
| 输入图像大小 | 28 × 28 |
| 输出类别数 | 10 |

选择该模型的原因是：它比简单 CNN 具有更强的特征提取能力，同时计算量仍然较小，适合在本地 GPU 上快速迭代实验。

## 4. 鲁棒微调阶段：Robust Expert

### 4.1 微调方式

鲁棒微调不是从零开始训练，而是从 Clean Expert checkpoint 初始化：

```text
outputs_submission/checkpoints/best_model_stat-09987e.pt
```

这样做的目的是保留预训练阶段学到的标准数字识别能力，并在此基础上增强模型对真实扰动的适应能力。

### 4.2 微调数据集

鲁棒微调阶段实际使用的数据源为：

| 数据源 | 样本数 |
|---|---:|
| MNIST-family | 141,833 |
| HASYv2 digits | 816 |
| Chars74K digits | 440 |
| UCI Pen-Based rendered | 26,381 |

其中 MNIST-family 包括 MNIST、EMNIST Digits、USPS 和 QMNIST。



### 4.3 采样权重

鲁棒微调使用 `WeightedRandomSampler` 对不同数据源进行加权采样：

| 数据源 | 采样权重 |
|---|---:|
| MNIST-family | 0.45 |
| HASYv2 | 0.20 |
| Chars74K | 0.10 |
| Pen-Based | 0.15 |


这种设置降低了 MNIST-family 的相对权重，提高了更接近真实书写风格的数据权重。

### 4.4 微调参数

鲁棒微调阶段的主要参数如下：

| 参数 | 取值 |
|---|---:|
| fine_tune_lr | 3e-5 |
| fine_tune_epochs | 30 |
| batch_size | 4096 |
| optimizer | AdamW |
| scheduler | CosineAnnealingLR |
| weight_decay | 1e-5 |
| label_smoothing | 0.03 |
| robust_aug_strength | strong |
| use_amp | true |
| allow_tf32 | true |
| compile_model | false |

batch size 的选择来自本次 benchmark：

| batch_size | samples/sec | 显存 allocated | 判断 |
|---:|---:|---:|---|
| 4096 | 6556.84 | 3.51 GB | 最快，最稳 |
| 8192 | 5147.77 | 5.81 GB | 更慢 |
| 12288 | 3280.23 | 6.55 GB | 明显更慢 |
| 16384 | 1436.96 | 8.15 GB | 接近显存风险 |

因此最终选择 `batch_size=4096`。

### 4.5 鲁棒增强策略

鲁棒微调使用 strong augmentation，主要配置如下：

| 增强项 | 参数 | 目的 |
|---|---:|---|
| RandomAffine | ±15° | 适应旋转、平移、缩放、切割偏差 |
| GaussianNoise | std up to 0.10 | 适应噪声和扫描退化 |
| GaussianBlur | p = 0.30 | 适应模糊、拍照不清晰 |
| Erode/Dilate | p = 0.45 | 适应笔画粗细、墨迹扩散、断笔/连笔 |
| CenterJitter | 3 px | 适应数字不居中 |
| Brightness/Contrast | 随机变化 | 适应笔画深浅和光照变化 |

这些增强使训练集难度明显高于普通 clean training，因此微调阶段的训练准确率较低是正常现象。

## 6. 验证与评估结果

### 6.1 Validation Board

项目使用 validation board 进行综合评估。它包含：

- `val_clean`：较干净的验证集
- `val_corrupt_lite`：轻度扰动验证集
- `val_external`：外部 holdout 数据

Clean Expert 和 Robust Expert 的结果如下：

| 模型 | val_clean | val_corrupt_lite | val_external | composite_score |
|---|---:|---:|---:|---:|
| Clean Expert | 0.998957 | 0.994416 | 0.997300 | 0.997861 |
| Robust Expert | 0.995911 | 0.991032 | 0.971760 | 0.989141 |

需要注意：Robust Expert 评估时 `val_external` 样本数为 94,546，而 Clean Expert 评估时为 60,000；Robust Expert 的 validation board 加入了 optional external data，因此难度更高，二者 composite score 不完全是同一难度下的直接对比。

### 6.2 官方 Holdout 测试集

官方 holdout 包括：

- MNIST test
- EMNIST Digits test
- QMNIST test10k

结果如下：

| 模型 | MNIST test | EMNIST Digits test | QMNIST test10k |
|---|---:|---:|---:|
| Clean Expert | 0.9973 | 0.9973 | 0.9973 |
| Robust Expert | 0.9951 | 0.9955 | 0.9951 |

Robust Expert 在标准官方测试集上比 Clean Expert 略低，下降约 0.18%-0.22%。这是因为 strong robust fine-tuning 会牺牲一小部分干净分布上的最优准确率，以换取对真实扰动输入的更强适应能力。

## 7. Ensemble 模型融合

为了同时利用 Clean Expert 的标准识别能力和 Robust Expert 的鲁棒性，本实验进行了模型融合。融合公式为：

```text
final_prob = clean_weight * clean_prob + (1 - clean_weight) * robust_prob
```

搜索结果如下：

| clean_weight | composite_score | val_clean_acc | val_corrupt_lite_acc | val_external_acc |
|---:|---:|---:|---:|---:|
| 0.60 | 0.983224 | 0.998618 | 0.994924 | 0.939257 |
| 0.55 | 0.984283 | 0.998449 | 0.994839 | 0.943953 |
| 0.50 | 0.985628 | 0.998280 | 0.994416 | 0.949993 |
| 0.45 | 0.987089 | 0.998054 | 0.994585 | 0.956275 |
| 0.40 | 0.987985 | 0.997913 | 0.994106 | 0.960485 |
| 0.35 | 0.988551 | 0.997828 | 0.993316 | 0.963425 |
| 0.30 | 0.988930 | 0.997603 | 0.993119 | 0.965604 |

当前搜索范围内最优权重为：

```text
clean_weight = 0.30
robust_weight = 0.70
composite_score = 0.988930
```

随着 clean_weight 降低，综合分逐步上升，说明当前 validation board 更偏向 Robust Expert 的输出。后续可以继续搜索 `clean_weight=0.0-0.3` 区间，判断是否存在更优融合比例。

---

## 8. 结果分析

本次实验体现出典型的精度—鲁棒性权衡：

1. **Clean Expert** 在标准官方测试集上表现更高，适合干净、规整的数字样本。
2. **Robust Expert** 在强增强数据上稳定收敛，更适合真实手写、位置偏移、模糊、噪声和笔画变化等复杂输入。
3. 鲁棒微调使标准 holdout 准确率下降约 0.2%，但该下降是为了提升真实场景泛化能力而产生的合理代价。
4. Ensemble 搜索显示模型融合时更偏向 Robust Expert，说明在综合验证板上，鲁棒模型的贡献更大。

---

## 9. 后续改进方向

后续可以从以下方向继续改进：

1. **补齐 Optical Digits 数据源**：当前启用了 Optical 配置，但本地目录不存在，实际没有使用。
2. **扩展 ensemble 搜索范围**：当前最优点在 clean_weight=0.30 的边界上，建议继续搜索 0.00、0.05、0.10、0.15、0.20、0.25、0.30。
3. **加入真实退化增强**：例如 JPEG 压缩、拍照阴影、透视变形、断笔、墨迹扩散等。
4. **构建真实手写验证集**：收集 50-200 张真实拍照/扫描/手写样本，作为更接近最终应用场景的人工验证集。
5. **尝试更大模型**：如 `large_cnn`，但需要从头训练 clean expert，再进行 robust fine-tuning。

---

## 10. 总结

本阶段完成了从 Clean Expert 预训练到 Robust Expert 鲁棒微调的完整流程。预训练模型在标准数字数据上取得了较高准确率；鲁棒微调模型在加入强数据增强和更多真实书写风格数据后稳定收敛，并增强了对复杂输入的适应能力。虽然鲁棒微调在标准官方测试集上略有下降，但这符合本实验提升真实场景泛化能力的目标。后续可通过补充真实退化数据、扩展融合权重搜索和构建真实手写验证集进一步提升最终表现。
